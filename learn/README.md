# learn/ · AlphaZero 五子棋教程

从零读懂这个仓库里的 AlphaZero 式五子棋系统：不仅知道每个部件做什么，还要能沿真实数据和代码说明它为什么存在、把什么交给下一环。

课程是**单一线性主线**：序章 + 18 课 + 毕业，共 20 个导航节点。每课按「具体问题 → 先动手观察 → 公式收口 → 真实代码落点」推进，复杂机制再拆成连续小步。

初始只解锁序章。每课的收束顺序是：**读到末尾 → 亲手完成本课产物 → 合书复述 → 回答导师的应用/纠错追问 → 由独立判定器检查证据 → 通过后才解锁下一课**。产物是学生自己写下的计算、观察或测试结果，不是选择题，也不等于系统自动执行了代码。答案唯一的计算题（第 1、2、3、15 课）会在保存时先做关键数值门禁；门禁也会拒绝“正确数字后面接否定结论”，但它仍不是全自动评分，自由设计题由导师和判定器核对步骤。判定通过不等于一定解锁：若进度写入失败，或写入后读回时发现记录损坏，页面会明确停在当前课，不会显示“已解锁”。损坏的本机进度也不会被静默清零；需要先备份，再重置。已通过的课可以回看，在本页面内不能靠点目录或改 URL 跳过。回看时答疑随时可用，但“合书复述”和“12 岁版”仍要求这次重新读到收束，不能拿旧通过记录冒充新一轮阅读。

五个能力阶段各有一个**阶段末课**：序–第 2 课、第 3–6 课、第 7–11 课、第 12–15 课、第 16–18 课 + 毕业。阶段末课除了本课目标，还要用自己的话完成一次跨课迁移；普通课至少需要 2 轮追问，阶段末课至少 3 轮。阶段内可通过右侧“本级阶梯卡”查看本级目标、练习、里程碑、常见错误和三条闭卷自测；通过本阶段前面的课程后，可以先用专用“本级三问”做验收前诊断，但诊断只暴露漏洞，不参与放行。

桌面端右侧常驻学习面板给出五级路径，以及每一级的目标、核心概念、动手练习、里程碑、常见错误和闭卷自测；“五级全图”可以逐级展开查看未来四级的验收标准，但提前看标准不会提前解锁。再往下一层是 20 小时主线、5 个信号源、7 天冲刺节奏、毕业项目和下一站；信号源和 7 天路径里的资源现在都能点开。窄屏不挤压正文，改从顶栏“路径”打开同一份面板抽屉，仍能随时查看当前位置与进度。浏览器 Back/Forward 回到旧课时会恢复上一课的阅读位置，不会每次都被打回顶部。掌握记录只保存在本机浏览器 `localStorage`（键 `alpha-gomoku-learn/progress/v1`），动手产物另存于每课独立键（前缀 `alpha-gomoku-learn/practice-artifacts/v1/`），费曼定稿另存于每课独立键（前缀 `alpha-gomoku-learn/feynman-notes/v1/`，旧聚合键仍可迁移读取），都不跨设备同步；它们是本机学习记录，不是防伪凭证，手动改浏览器存储可以伪造记录。页面不显示选择题；旧题只作为导师“考我”的内部考点。

页面右下角的“问导师”连接本机 Codex：你在对话里说哪里没懂、要求换例子、合书复述或让它考你。导师会带上当前课、当前小节、主动选中的原文、本课内部题库和本轮对话；复述模式还会带上已提交的动手产物，判定请求也会带。回复直接写回页面。桌面和窄屏都使用真正的模态面板：背景不可点击、不可聚焦，关闭后焦点回到原触发按钮；原按钮因阶段变化被替换时，焦点回到本课标题。右上角“继续读正文 / 继续动手 / 继续复述 / 回到判定”只关闭面板，不会替用户换课或推进。两个标签页同时修改同一课产物时，页面不会静默覆盖，会让你选择“载入新版本”或“保留我的草稿”。导师不会编辑代码，也不会假装看到当前这条 Codex 工程会话。普通对话不持久化；只有导师在费曼循环里明确给出、且带成对标记的“导师整理版费曼定稿”会自动保存到本机，供侧栏和课末回看。它不是学生亲笔存档，复制它回导师也不会被当成有效复述。

## 六种学习方法怎样落地

1. **学习阶梯**：右侧“五级台阶”给出每一级的能力目标；展开“本级阶梯卡”看当前级要求，展开“五级全图”可以逐级查看全部五级的目标、核心、练习、里程碑、常见错误和闭卷自测。阶段不会因为“读完”自动晋级，仍以阶段末课的跨课迁移判定为准。
2. **20 小时主线**：把 20 个课程节点压成 10 个约 2 小时的单元，每个单元都有“为什么先学”、目标、核心概念、推荐资源、练习、产出和 5 个复习问题。它是排期框架，不是倒计时；掌握不够就停下补。本单元全部通过后，可展开 5 问并用导师做单元复盘。
3. **主动考问**：导师的“考我”是一个问题一个问题地问，按回答给分、指出漏洞、只补当前缺口，最后才给强弱项和复习建议。快问 3、单元 5、阶段 3 和完整 10 各自答完主问题后收束；只有学生明确说“停止考问”等指令才允许提前收卷。通过后侧栏和课末都能直接启动快问 3 或完整考问 10；单元卡启动复习 5；本级自测另走严格的阶段三问。它不显示选择题，也不参与线性放行。
4. **一页速查卡**：每课通过后展开“一页速查卡”，包含一句话模型、因果流程、3 个具体例子、常见错误、使用前检查和 5 个可折叠快问快答。通过后右侧可以直接“打开一页速查卡”，不用每次重新翻到课末。它只用于 5 分钟复习，不替代合书复述。
5. **资源策展**：右侧只列 5 个高信号源——课程主线、`PLAN.md`、`alphagomoku/`、测试与对拍、真实记录与 run 产物——并给出 7 天冲刺节奏和一条明确的“别拿它做什么”。每项都有可点击入口，7 天路径也会直接链到对应来源。目标不是收集更多资料，而是知道下一次该查哪里。
6. **费曼循环**：课末先合书讲三件事；导师指出讲对的部分，只补最小漏洞，要求应用、纠错，阶段末再要求跨课迁移。讲干净后，导师会给出带起止标记的可复制定稿，页面自动存到本机并标为笔记；它不是判定，也不会自动解锁课程。点“12 岁版”会先得到一段简单解释，随后自动交回复述模式，让学生接着讲；讲不清就不能进入下一课。复述通过后仍可用“速查卡复习队列”按通过时间回看已通过的课；队列不排自动闹钟，也不假装知道你的遗忘曲线。

20 小时主线之后还有一个迁移项目：换一种明确规则（例如把五子棋改成四子棋），从胜负判定、样本、训练、竞技场一直改到网页验收。它用来证明你能把整套技能搬走，而不是只会复述当前仓库。

## 学习契约

这套流程把“感觉懂了”拆成四类可检查的动作：

1. **解释**：不用原文术语，能讲清核心因果、条件和“为什么”。
2. **应用**：能把规则用到一个新的数字、棋盘局面或代码片段，而不是复述正文原例；本课动手产物会作为这项证据的必查材料。
3. **纠错**：能指出一个常见错误、边界，或说明某个做法为什么不行。
4. **迁移**：阶段末课还要把本阶段至少两个概念串起来，完成一次跨课场景。

建议一次只学一课，20–40 分钟；新课开头先回答右侧“上一课 · 30 秒回忆”，想不起来就回上一课看速查卡。卡住就先问一个最小问题，不要带着断层往下滑。到课末先把这一课亲手做一遍并记录产物，再合书复述、申请判定。判定通过后不要立刻刷下一课：先点“3 分钟快问”，第二天再打开速查卡做一次闭卷回忆，然后继续新内容。阶段末课前用“本级三问”查漏；单元全部通过后做 5 问复盘。每课开头的一问、课后的快问和速查卡一起构成“路径 → 测试 → 压缩 → 重复”的闭环；它们都不参与放行。间隔复习比连续刷课更稳。

## 本机导师

导师桥只在 `npm run dev` / `npm run preview` 时存在，不进入静态构建。它调用本机 `codex` CLI，因此需要：

```bash
codex --version   # 应能正常输出
```

页面把对话请求发到同源的 `POST /api/tutor`，把掌握判定发到独立的 `POST /api/tutor/assess`。判定器只读取学生自己说出的证据，并有服务端证据护栏：普通课至少 2 个合书复述轮次、阶段末课至少 3 个；证据必须分属解释、应用、纠错三类，阶段末还必须有一条跨课迁移。答疑和“考我”的发言不会冒充复述轮次；“嗯”“懂了”这类空话也不计轮次或证据来源。应用证据必须逐字回到动手产物，产物照抄导师解释或正文会被拒绝。浏览器里没有 API key，导师进程以只读沙箱运行，只接受 `localhost`、`127.0.0.1` 或 `[::1]` 回环 Host，以及同协议、同主机、同端口的 Origin，不再接受任意指向回环地址的域名。默认使用本机 Codex 配置的模型，也可以用 `CODEX_TUTOR_MODEL` 覆盖。`dist/` 必须通过 `npm run preview` 或任意静态 HTTP 服务器打开；直接双击 `file://` 会因模块/CSS 的 CORS 限制空白，且没有本机导师桥。纯静态部署时新用户只能阅读序章，无法产生新的导师判定或解锁后续课；已有本机通过记录的浏览器仍可回看已解锁内容。页面会提示未连接。

这是一套学习闭环，不是防作弊系统。阅读进度、对话历史、动手产物和“读到末尾”的凭证都由当前浏览器提供；服务端会用课程契约和证据原话做结构校验，但没有独立的账号会话账本，无法阻止有人伪造请求或手改 `localStorage`。第 1、2、3、15 课的确定数值会在客户端保存和服务端判定前各查一次；其他动手产物仍是自由文本，系统不会自动运行 Python、测试、对战或检查文件。`digest` 只用于发现本机误改/错配，不是防伪签名。费曼定稿同样只是本机笔记，丢失或伪造都不改变导师判定。它适合自己认真学，不适合拿来发证书。

旧的选择题数据没有删除，而是转入导师内部题库：页面不渲染选项，只有学生主动点“考我”时，导师才会把考点改写成开放式问题，一次问一题。

主线依次覆盖：

1. 棋盘、动作与当前方视角；
2. 参数、损失、点积与 ReLU；
3. 三输入面、卷积、残差/BN 与策略价值双头；
4. MCTS、PUCT、回传、根噪声、温度和访问分布；
5. 自我对弈 `(s, π, z)`、回放池、增广、双损失与优化；
6. 竞技场、迭代恢复、run 目录、服务器与浏览器数据边界。

## 真实性口径

- 浏览器加载 demo run 导出的真实 checkpoint 权重；`tests/parity.test.ts` 用 16 个输入、6 组中间/输出张量与 torch 结果对拍。
- TypeScript 引擎遵守 Python 核心契约，但不是逐位相同的运行时：网页固定 9×9，导出权重保留 5 位小数，使用 JS 数值/RNG、单局顺序搜索和较小预算。课程将这些标为“浏览器适配”，不声称执行结果完全相同。
- 每个组件分别标明来源：训练归档的**真实记录**、按项目逻辑重新计算的**真实代码复现**、隔离机制的**教学构造**，或预算/精度不同的**浏览器适配**。不存在“页面上每个数字都来自训练记录”的总括承诺。
- 归档逐手 `value` 的含义是 MCTS 回传后的根节点平均值(`root_value`)，不是价值头裸输出；训练从 `(s, π, z)` 重算网络价值。`π` 的分母是全部根访问数，不能用 top-5 摘要重新归一化。
- `PLAN.md` 是项目设计契约；教学内容同时通过 Python 实现、TS 镜像、测试与生成产物交叉验证。发现契约漂移时先修正或明确登记，不能把冲突说法都当作正确答案。

## 运行

```bash
cd learn
npm install --registry=https://registry.npmmirror.com
npm run dev      # http://localhost:5173
npm run build    # tsc + vite build → dist/
npm test         # 引擎、课程清单、产物一致性与对拍测试
```

## 重新生成真实产物

源 run 位于 gitignore 的 `data/runs/demo/`。重新训练或更换 checkpoint 后，从仓库根执行：

```bash
.venv/bin/python learn/scripts/export_weights.py
.venv/bin/python learn/scripts/dump_expected.py
.venv/bin/python learn/scripts/dump_mcts_trace.py
.venv/bin/python learn/scripts/provenance.py generate
```

随后运行 `npm test`，确认导出权重、期望张量、MCTS 轨迹和浏览器引擎仍然一致。课程使用的生成物会记录 run/config、checkpoint role/meta、SHA-256、导出 schema 与代码版本；没有源 run 的干净检出仍可运行 `.venv/bin/python learn/scripts/provenance.py verify` 校验已提交产物，但不能重新生成它们。

更长的成人讲义仍保存在 `archive/`，`../explainer/` 是介绍站；它们是冻结的旧版长文，不替代教学主线中的任何必修概念或源码对证。若旧文中的课号、交互参数与主线冲突，以当前课程和源码为准。
