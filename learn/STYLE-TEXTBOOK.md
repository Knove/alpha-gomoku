# 教材体例手册(learn/ 全站改写契约)

目标:大学标准教材水准,深入浅出。读者=无 AI 背景的程序员。
本手册覆盖:章节结构、前瞻纪律、术语体系、文风、UI 体例。任何课文改动先读本手册。

## 一、章节结构(每课固定,顺序不换)

毕业章为结语体,结构例外:六条结论与毕业词作为正文收束,允许排在例后、对证前与章末。序章为前言体,结构例外:导读 → 系统总览图 → 思考题 → 正文 → 真实回放(眉签「真实记录」,不入例序)→ 章末。序章正文允许"预览括注"与预告式 Def(带 see="第 N 课" 指向正式立目章),但不得使用"第 N 课教你/会讲"式承诺句;承诺一律走章末。系统总览图(SystemPreview)与回放是前言的组成部分,不受例序约束。毕业章的「对证」是核对清单体(读者动手逐步核对一盘棋),不用 Ledger、不列源码,属结语体例外。序章正文的预览括注含「参见:第 N 课」亦属允许,不算前瞻违规。

```
第 N 课 · 标题(h1 不改,与 curriculum.ts 对齐)
  <LessonGuide>   导读:问题 / 为什么现在学 / 本章路线 / 学完你能说清 / 范围
  <Quiz>          思考题(title="思考题 · 先选一个答案")
  正文            连续论述,分 § 小节(h3 用陈述句标题)
    <Def>         关键术语就地立目(见三),正文随后直接用名
    例 N-M        交互部件就地插入(原"部件"改称"例");原则上紧跟用到它的段落,
                  同一驱动链的例允许集中排在正文后、对证前(范本 L03 即此排法)
  <Ledger>        对证(真实代码)
  <ChapterEnd>    本章小结 + 下节预告
  <Quiz>          习题(title="习题 · 过关解锁第 M 课")
```

## 二、前瞻纪律(根治"第 4 课教你"的补丁感)

- 正文行文**零跨章前瞻**。只允许回指已教内容("第 2 课的视角约定")。
- 前瞻只许出现在这些位置:①导读的"范围"句(全章仅一处);②`<ChapterEnd>` 的"下节预告";③`<Def>` 的"参见";④习题解锁按钮文字("过关解锁第 M 课");⑤对证(Ledger)评注、思考题/习题解析、例内说明文字里的"参见:第 N 课"式引用(等同 ③,允许)。序章的路线图属于总目录职能,不受此限。
- 同章内指向下文的过渡句允许,每节至多一处,只许说"下文/下一节"不许报课号(如"步幅由下一节的学习率控制")。
- 常见违规句式(发现即改):"第 N 课教你/细讲/展开/再算总账/接回来"、"以后会完整推导"、"下一课再说"。
- 改法:把该句整段迁到下节预告;若正文因此缺了必要交代,就地用一行定义框"参见:第 N 课"替代,不要在行文里悬一句预告。

## 三、术语体系(与既定术语政策一致,呈现升级为定义框)

- 关键术语首现用 `<Def term="中文名" en="English name">定义 + 机制</Def>` 立目;正文此后直接用名,**不再挂括号补丁**。凡涉及可计量概念,定义还须给出**单位与判据**(范本:L03 Def「特征」:一个问题就是一个特征,答案就是特征值)。
- 括号内嵌"(英文名+机制)"只允许出现在非关键术语、例与交互部件的说明文字、表格/代码注释里。
- 白名单例外:第 3 课 Def「损失」内保留一次"(直观叫它罚分也行)"括注;除此之外"罚分"全站禁用。
- Def 字段规范:term=中文名,en=英文名;代码标识符作 term 时(如 min_buffer)尽量配中文名(term="最小样本门槛" en="min_buffer")。
- 禁口语化替身(旋钮/罚分/谷底/下山/计票/模板/检测器/得数/老师/作业/对账/大脑/开练/换号 等历史清单继续有效);量词统一:个权重、个卷积核、个平面、张特征图。
- 已立目的术语跨章复用时可直接用名;若读者可能淡忘,用 `<Def see="第 N 课">` 复习框,不重开长解释。

## 四、文风(深入浅出)

- 陈述句连贯成段,每节 2-5 段,每段一个论点;禁止三行以内的碎片段落连发。
- 禁补丁腔:"还要钉死一个点"、"注意别误读"、"容易误解的是"、"这里要澄清"。理解缺口用主线设计解决,不写勘误式旁白。
- 破折号(——)全站**零容忍,硬门禁**:任何文本改动提交前跑 `rg '——' src` 必须零命中;插入语用括号或冒号,句间用句号。历史上两度回潮,不得再犯。
- 数字示例先行,公式跟上,概括收尾(深入浅出的次序)。
- 诚实边界保留:玩具与真实记录、演示配置与默认配置、浏览器适配的差异照旧声明,但用陈述句自然带出,不作警示腔。

## 五、UI 体例(绑定 taste-skill + frontend-design 规范)

- 两族字体:正文/标题=中文衬线(`--font-serif`),代码/数字/眉签=等宽(`--font-mono`)。禁止第三族。
- 全站一个强调色(朱砂,品牌既有);一个圆角体系(14px 沿用);暗色主题照旧。
- 结构即信息:眉签只保留真实信息("第 N 课"、"例 4-1"、"对证");禁 ALL-CAPS 装饰眉题、序号眉题(01/02)、中点串标签。
- 少卡片:定义框用左侧墨线+纸底,不用阴影圆角卡;图(例)保留卡片容器但一课内不堆同构卡。
- 标题层级:节标题用陈述句(如"棋理写在配对里"),不用"揭晓 · xxx"式的讲台腔。
- 动效只留交互反馈(:active 轻压);不做入场动画。

## 六、冻结项(任何改写不得触碰)

- Quiz 的 `answer` 下标值、所有 `data-qa` 属性。
- 忠实性不变量:v_net/root_value/z 语义、π 分母=ΣN、arena 口径(胜1和0.5负0、promote_threshold=0.55)、metrics 先于 checkpoint、buffer.npz 非原子、resume 口径、48×27=1296、145,050≈14.5 万、感受野 7层→15/9层→19、temp_threshold 12/10、c_puct=1.5、dirichlet ε=0.25/α=0.3、lr=0.01、momentum=0.9、weight_decay=1e-4、池子五万、批次 128。
- 各课 h1 与 curriculum.ts 的 title 对应关系(文件号与课号错位映射见 lesson.ts)。
- 代码节选的行号与内容可微调注释措辞,不得改动代码本身。


## 七、概念口径审计清单(每次全文审校按此七类过一遍)

1. 定义缺单位判据:可计量概念的 Def 必须给出单位与判据(范本:L03 特征、L16 原子)。
2. 例子误导读法:例中的数值、图形、代码不得换角色而不点破;展示归一/裁剪须声明「这是展示变体,不是量本身」。
3. 口径漂移:同一概念全书唯一名;口语别名至多在立目处出现一次,随后弃用。量词表:个权重、个卷积核、个平面、张特征图、个通道、条样本、局棋、次模拟、轮 iteration、份 checkpoint、行 JSONL 记录。
4. 跨章桥断裂:形状相同的量(如 P 与 π、两处「热度」)跨章换指时,新章首用处必须一句桥接「与第 N 课的 X 不同在…」。
5. 一词多义:高危词(分数/热度/读/轮/价值)各义项限名,禁止同章两名。
6. 打包单位不清:复合对象(s,π,z / checkpoint / 一行 JSONL)须写明「一份打包里有几个数」,并声明要素≠特征。
7. 角色翻转未点破:同一串数字换角色(特征值→输出分数→logits→P→π→N 比例)时,正文必须有一句「同一串数字,上一阶段是 X,这一阶段是 Y」(范本:L04 加权和、L08 特征图)。


## 八、写透标准(追问审计清单,每次全文审校必过)

对每个断言模拟爱追问的读者(为什么?一定吗?如果…呢?和…矛盾吗?),按七类判定并修:
1. 没写透:只答"是什么"缺"为什么/否则会怎样";推导给结果不给中间步(链式、代数变形要写全)。
2. 含糊:两种读法并存。
3. 不准确:表述过松或错(如把凸函数性质写成梯度通则、把局部变化率叫梯度)。
4. 易误解:存在自然的错误读法,且与代码/后文打架(如"一格不合并"vs Linear(162,81))。
5. 未言明前提:零和、不可导点约定、固定种子、退化示例等暗前提要写明。
6. 边界未覆盖:0 输入、尺度差、盘沿、退化、吸收态(梯度 0 不动点)等。
7. 承诺未兑现:凡"参见/预告"指向处必须真有答案;口号不得超出证据域("这张核"不升格为"卷积核")。
另:设计取舍要给被否方案与理由(如 REST+WS vs 轮询);事实断言必须与代码/数学精确一致(残差块各层顺序、统计的维度、角部感受野)。
